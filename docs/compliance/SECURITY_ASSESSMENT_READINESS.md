## 2. 用普通话说明现状

### 2.1 身份认证和注册留存：已有门锁，但通行路径和出入记录不完整

**已做到：** 后端能拿微信给的一次性授权码向微信服务器换手机号；它不是直接相信用户填的手机号。主要评价/反馈接口会拒绝未认证和封禁账号。账号表保存了账号编号、注册时间、手机号认证时间等。历史账号不会迁移成“自动已认证”。

**还差什么：**

1. 网页登录使用一种登录凭证（Cookie），旧评价/反馈入口只识别另一种凭证（Bearer）。因此可能出现“页面显示已登录且已认证，提交时却说没登录”。不是认证可以随意绕过，而是正常用户的链路没接通。
2. 目前记着“最后一次登录时间”和“累计登录次数”，不等于逐次记录“哪天、哪个账号、从哪里登录、成功还是失败”。例如只知道共登录10次，无法追查第7次发生了什么。
3. `/api/v1/me` 是登录后查看本人资料的接口，却返回完整内部用户行，含手机号、openid和密码哈希。这不等于匿名访客已能直接读别人的资料，但返回字段过多，还带公共缓存指令，需要修。
4. 私密投诉目前也套用了公开投稿门槛，匿名被挡住；这与C-05不符。网站也没有完整举报表单。
5. 旧库若有 `openid NOT NULL` 约束，网页注册写空openid会失败；这是合成旧库验证的条件性问题，未断言生产一定用了该旧结构。

对应任务：UGC-02、MIG-03、REP-06、AUD-09、SEC-01、WX-22。

“存400天”只解决**已经写下来的记录多久删除**，不能解决**当时根本没写记录**。目前查询只显示最近100/300条，也不等于旧日志被删除；这是查不全，和保存不够是不同问题。

所谓源端口，是网络连接的一个数字标识。例如用户先连接Caddy、Caddy再连接Node，Node看到的连接端口可能属于Caddy，不能把它冒充成用户的真实源端口。应在能看到真实连接的入口记录，并说明有无上游代理。

### 2.3 审核和举报：基线曾将“事情办完”理解为“允许公开”

一个用户提交普通反馈，管理员只想把处理状态改成“已完成”，当前代码就可能把它展示给所有访客。对举报虽然当前类型会被排除，但管理员改了类型后，这层保护会失效。

要改成两个独立决定：“处理到哪一步”和“是否批准公开”。举报的私密性质不能随处理状态或类型一起改变。只有普通公开投稿才有批准公开的选项。

对应任务：MOD-04、REP-05、ADM-07、ADM-08。

### 2.4 查询与导出：所有有效管理员均可使用，不再拆分权限

“查询”是在后台查看某个范围的资料；“导出”是把资料打包成可下载、可复制的文件。后者更容易离开系统的控制范围。

目前一个 `law.manage` 权限同时允许两者，但其他没有该权限的管理员可能被拒绝。用户于2026-09-29明确决定：所有有效管理员都应能查询和导出，因此不拆成两个权限，也不设置“仅查询管理员”。

LAW-15据此改为验证和落实“管理员可用、非管理员不可用”，以及保留审计。不能把“管理员不做区分”实现成接口不鉴权，不能取消谁查过/导出过什么的记录。真实管理员账号密码仍不需要提供。

### 2.5 注销：现在确实还留有用户数据，需要明确分哪些数据处理

基线 `server/mp-auth-service.mjs:303–309` 的实际动作：

| 数据 | 现在注销后的行为 |
|---|---|
| 登录会话 | 删除所有该用户token，旧登录凭证失效 |
| 微信openid、网页密码哈希 | 清空 |
| 头像、email | 清空 |
| 昵称 | 保留原昵称，再加“_已注销”后缀，并非擦除原昵称 |
| 手机号、手机号认证时间 | 仍保留 |
| 评价/反馈/举报与用户ID的关联 | 仍保留，未实际解除 |
| 安全日志、历史备份 | 不能当作注销时全部同步删除；具体生命周期尚未完整落实 |

所以目前既不是“全部删除”，也不是“把身份抹去，只留下匿名内容”。仅加“已注销”后缀、隐藏公开昵称或换成数字ID，也不一定是真正匿名化。

建议采用分类方案（**建议，尚待用户确认D-01**）：

- 正常业务系统停用账号、撤销会话，清除不再需要的身份绑定与个人资料。
- 已公开内容是否继续展示，应结合用户选择、告知和合法处理依据处理；若保留，移除公开身份信息，并处理正文中可能出现的个人信息。没有满足匿名化条件时不能称为“彻底匿名”。
- 依法确需留存的安全记录或特定争议材料，在明确范围、依据、期限后限制使用；不因一句“以后监管可能需要”而永久保留所有手机号及全部正文。
- 备份需要明确到期清理和恢复后重新应用删除记录的机制，防止从旧备份恢复出已经注销的活跃账号。

《个人信息保护法》第19条要求必要的最短保存期限；第47条规定相应删除义务，并对法定期限未届满、技术上难以删除的情形限制继续处理。它不支持“一律无限保留”，也不支持忽略法定留存而一键删除所有材料。依据：[官方全文](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)。以上是产品与技术建议，不以用户选择取代适用的法律义务。

### 2.6 模板里的通讯群组、转发、硬件特征是什么

- 通讯群组：类似群聊，让一群用户在同一个空间交流。普通课程列表或一条评价不是群聊。
- 转发：平台内把其他用户的内容再发布/传播的功能；外部浏览器复制网页链接不当然等于平台已提供站内转发功能。
- 客户端硬件特征：用来描述或区分设备的信息；浏览器User-Agent主要说明软件/系统，不能当作准确硬件指纹。
- PDF栏目兼顾多种互联网服务。当前没提供的功能应说明不适用，不能为了填满标题去开发，也不能虚报“已采集硬件指纹”。是否需要额外字段，按实际服务及受理要求确认。
