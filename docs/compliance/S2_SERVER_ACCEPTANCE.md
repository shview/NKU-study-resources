### 2. 入口日志

核对服务器Caddy版本。当前模板实际验证版本是2.11.4；在原配置顶层导入 `ops/Caddyfile.s2-log-snippet`，在网站实际入口site block里 `import s2_access_log`，不要覆盖已有路由/TLS配置。

创建Caddy可写、非公开的日志目录（示例用户为caddy，若实际不同需对应调整）：

```sh
sudo install -d -o caddy -g caddy -m 0700 /var/log/nkustudy
sudo -u caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

上例仅适用于实际服务用户为caddy、路径和配置环境相符的部署。验证须使用实际服务的用户、环境变量及必要文件访问权限；若依赖环境文件，按实际服务配置传入，不回显秘密。已有日志应先核对文件及目录属主、模式与服务用户可写性；不得截断现有日志来“修复”权限。

本次部署事故回执：root执行validate产生root属主日志，服务重启两次失败，累计约2.5分钟不可用，维护者已修复复测。此处补足原操作单未明确的身份要求。`validate`会实际加载和初始化模块，可能产生文件操作；不要假设它不会创建日志文件。官方命令说明见 [caddy validate](https://caddyserver.com/docs/command-line#caddy-validate)。纯`adapt`只做配置转换，不能替代资源权限验证。对运行中服务应考虑模块独占资源，维护者按实际模块选择隔离验证或受控reload，不以先停站点作为通用前置步骤。

先验证成功再按现有发布流程重启Caddy。官方说明：同一日志文件的输出配置改变需要重启，普通reload可能不生效；`roll_keep 0`会回到默认数量限制，模板使用`-1`关闭数量淘汰，`9600h`为400天。出处：[Caddy日志配置](https://caddyserver.com/docs/caddyfile/directives/log)。这不是对适用法律期限的判断。

可以先在服务器执行完全隔离的合成检查：

```sh
CADDY_BIN=/usr/bin/caddy node scripts/verify-s2-entry-log.mjs
```

预期：两种拓扑均 `ok:true`；脚本只监听回环随机端口。随后对正式入口发送一个普通合成路径请求，核对本地日志中的时间、方法、路径、状态和来源；不要以“已写配置”代替实际记录读回。

- 没有CDN：Caddy的`remote_ip/remote_port`就是直接连接客户端。
- 有CDN：它们是CDN节点地址/端口；`client_ip`只有在精确配置可信CDN地址范围和正确头后才能认作客户端来源。仍不知道最终用户端口时，写“不可得”，不能用CDN端口代替。
- Node只信现有明确的Caddy代理地址，公网不能直连Node端口。不要把任意互联网地址列为可信代理。
- 日志去掉全部查询参数和请求/响应头，只单独保留UA；不得启用`log_credentials`，不得另建未脱敏的重复访问日志。检查默认运行错误日志是否另行复制URL/头。

归档和容量（仍由维护者在服务器安排，未替用户创建后台任务）：

```sh
node scripts/archive-entry-logs.mjs /var/log/nkustudy /受控私密盘/nkustudy-entry-archive
```

该命令复制已关闭的滚动文件并哈希读回，保留期内源文件不删，失败以非零退出码报错；超过400天才按最新记录时间清理。活动日志不截断。目标必须由运行该命令的受控账号访问、目录0700。请通过现有systemd timer/备份维护任务每天执行，保存成功/失败结果并设置失败通知；不要把归档放公开网站目录或公开资源桶。

按实际每日字节数估算400天所需空间，并预留滚动/备份临时空间。检查磁盘用量告警和日志写失败告警可达维护者；Caddy磁盘满时不能承诺请求一定失败，因此必须依赖入口告警/限流或临时维护处置，不能冒称绝不丢访问日志。回传Caddy版本、脱敏字段样例、保留设置和容量/告警结论，不发整份生产日志。

### 5. 恢复演练及到期清理

以下路径均应由朋友替换成实际受控路径；恢复目标必须从未存在，不能写正在运行的目录：

```sh
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs verify /受控目录/runtime-备份.json.enc
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs restore /受控目录/runtime-备份.json.enc /新的隔离恢复目录
```

预期：验证输出`verified:true`；恢复输出`restored:true, quarantined:true, sessionsRevoked:true`。恢复后的SQLite能读到合成账号、评价/反馈归属、安全/管理员/调取日志，JSON哈希对应清单；旧会话为空，注销账号仍保持该快照中的注销状态。错口令或损坏文件必须非零退出，不能得到成功报告。

`.restore-quarantine`会阻止该目录直接启动。**旧备份拍摄之后发生的注销、删除、封禁等变化必须先核对并重新应用。D-01尚未决定，当前没有“一键解除隔离并自动上线”的工具。** 不要删除标志来绕过检查。恢复服务还需按维护流程配置秘密路径和资源桶，重建静态发布，不能把隔离目录直接当旧生产目录使用。

日常到期清理可以纳入朋友现有维护任务：

```sh
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs prune /实际DATA_DIR/private-backups
```

仅验证后清理超过400天的备份，无数量上限淘汰。口令更换后旧包必须用旧口令单独核验/维护；无法解密时命令失败并保留，不会猜测删除。明确S5分类保留策略后再调整工程窗口。
