# S2 上线操作与验收单

本轮已做完本地修复和合成验收，**尚未上线**。S1登录已由用户确认正常，不用再次办理手机号授权或重发S1。这里是S2候选版本的上线步骤；由用户安排朋友维护者执行，助手没有登录服务器或获得自动部署授权。

## 接收固定版本

正式交付包 `RELEASE.json` 给出完整提交编号、基线 `af2cf13`、分支 `codex/s2-logs-20261001` 以及打包时的推送状态。先读包内 `README.txt`，核对 `SHA256SUMS`，按其中的Git bundle方式在新的候选目录检出；包内另有源码归档及补丁。三者对应同一份代码，只需选一种，不重复应用。

如果还没有远端分支，Git bundle可直接把固定提交传给已有同仓库的维护者。源码包不含依赖、生产配置、数据库或构建产物，须按锁文件安装依赖。收到材料后先复核和复跑；部署完成仍需以下生产回执。推送状态不代表部署状态。

## 用户要做的事

1. 把完整交付包发给朋友，包内代码与操作单配套；先看 `S2_ACCEPTANCE.md` 的“如何核验四项承诺”：明确操作、预期结果、原始证据和未完成部分，无需凭助手的完成声明确认通过。朋友接手后应先独立运行 `node scripts/verify-s2-claims.mjs --output /tmp/自己选一个未存在的证据目录`，再按下面的维护者步骤核验和部署。固定版本以 `RELEASE.json` 为准。
2. 朋友完成部署并反馈后，用已登录的正常账号改一次非敏感资料；刷新确认保存。管理员在审计页应能看到自己的管理查询/处理时间、对象及结果。用户日志由朋友按合成账号编号在受控环境核对，勿把真实手机号或Cookie贴到聊天。
3. 如需自己保管加密备份，在后台备份设置填写至少16位口令，存到自己的密码管理器，不发给助手；保存后点“下载整体备份”。应得到 `.json.enc` 文件，朋友在服务器用私密口令文件验证。忘记口令无法从密文恢复；更换口令前保留验证旧副本所需的旧口令。

失败时回传：操作名称、北京时间、状态码/错误文字、合成测试条目的编号。截图遮掉账号资料；不要回传密码、口令、Cookie、微信code或备份内容。没有S2代码上线前，旧后台不会具有这些新行为。

### 2. 入口日志

核对服务器Caddy版本。当前模板实际验证版本是2.11.4；在原配置顶层导入 `ops/Caddyfile.s2-log-snippet`，在网站实际入口site block里 `import s2_access_log`，不要覆盖已有路由/TLS配置。

创建Caddy可写、非公开的日志目录（示例用户为caddy，若实际不同需对应调整）：

```sh
sudo install -d -o caddy -g caddy -m 0700 /var/log/nkustudy
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

先验证成功再按现有发布流程重启Caddy。官方说明：同一日志文件的输出配置改变需要重启，普通reload可能不生效；`roll_keep 0`会回到默认数量限制，模板使用`-1`关闭数量淘汰，`9600h`为400天。出处：[Caddy日志配置](https://caddyserver.com/docs/caddyfile/directives/log)。这不是对适用法律期限的判断。

可以先在服务器执行完全隔离的合成检查：

```sh
CADDY_BIN=/usr/bin/caddy node scripts/verify-s2-entry-log.mjs
```

预期：两种拓扑均 `ok:true`；脚本只监听回环随机端口。随后对正式入口发送一个普通合成路径请求，核对本地日志中的时间、方法、路径、状态和来源；不要以“已写配置”代替实际记录读回。

- 没有CDN：Caddy的`remote_ip/remote_port`就是直接连接客户端。
- 有CDN：它们是CDN节点地址/端口；`client_ip`只有在精确配置可信CDN地址范围和正确头后才能认作客户端来源。仍不知道最终用户端口时，写“不可得”，不能用CDN端口代替。
- Node只信现有明确的Caddy代理地址，公网不能直连Node端口。不要把任意互联网地址列为可信代理。
- 日志去掉全部查询参数和请求/响应头，只单独保留UA；不得启用`log_credentials`，不得另建未脱敏的重复访问日志。检查默认运行错误日志是否另行复制URL/头。

归档和容量（仍由维护者在服务器安排，未替用户创建后台任务）：

```sh
node scripts/archive-entry-logs.mjs /var/log/nkustudy /受控私密盘/nkustudy-entry-archive
```

该命令复制已关闭的滚动文件并哈希读回，保留期内源文件不删，失败以非零退出码报错；超过400天才按最新记录时间清理。活动日志不截断。目标必须由运行该命令的受控账号访问、目录0700。请通过现有systemd timer/备份维护任务每天执行，保存成功/失败结果并设置失败通知；不要把归档放公开网站目录或公开资源桶。

按实际每日字节数估算400天所需空间，并预留滚动/备份临时空间。检查磁盘用量告警和日志写失败告警可达维护者；Caddy磁盘满时不能承诺请求一定失败，因此必须依赖入口告警/限流或临时维护处置，不能冒称绝不丢访问日志。回传Caddy版本、脱敏字段样例、保留设置和容量/告警结论，不发整份生产日志。

### 3. 应用日志与管理员审计

发布并重启后，在运行服务的环境下（从原systemd环境取得真实路径，不用聊天提供秘密）执行：

```sh
DATA_DIR=/实际运行JSON目录 STATE_DB_PATH=/实际SQLite路径 node scripts/s2-storage-health.mjs
```

预期：`integrity:"ok"`、`privateFiles:true`、三个队列计数0；后台审计页无恢复告警。运行期间的一瞬间在途请求可能让队列非0；30秒后再看，持续增长即失败。

使用合成账号做一次登录/投稿/退出、合成管理员做一次状态修改与一次查询。后台管理日志有实际管理员、对象ID、结果、字段名及状态；用户事件编号对应实际内容。由所有有效管理员使用受控API查询/导出均应成功，未登录和停用账号401；一般管理功能原权限不变。S4的调取页面整修仍待后续，不能据此声称整个S4已交付。

按时间/目标查日志例子（在已登录后台同源页面通过维护者工具发送，不把Cookie放命令历史）：

```text
/admin-api/audit?kind=user&user_id=合成ID&page=1&page_size=100
/admin-api/audit?target=review:合成内容ID&page=1&page_size=100
/admin-api/law-query?type=account&value=合成ID&log_page=1&log_page_size=100
```

若发现 `durable-log` 告警、`LOG_UNAVAILABLE`、`LOG_OUTCOME_UNKNOWN`、`interrupted`：保留 `log-queue/` 和归档目录，检查磁盘、权限、SQLite锁；修复后等30秒或重启再查。结果未知的操作先核对实际业务记录，勿直接重复提交。不要在生产上主动制造磁盘满或破坏数据库；故障注入本地已经完成。

### 4. 完整备份与私密存储

后台完整备份新增强制加密，至少16位口令。口令另存0600的私密文件，供下面CLI读取；不要写入仓库或命令行参数。

生产完整包会读取：所有现有运行JSON（含通知/服务/AI等配置）、SQLite全部表、补写队列、用户/管理员/调取归档、管理员签名秘密，以及服务器配置文件。以下环境变量如未设置，默认路径分别为：

```ini
BACKUP_ENV_FILE=/etc/nkustudy/admin.env
BACKUP_CADDY_FILE=/etc/caddy/Caddyfile
BACKUP_SERVICE_FILE=/etc/systemd/system/nkustudy-admin.service
```

**应核对实际路径。** 原部署文档曾出现 `/etc/nkustudy-admin.env`，不要假定默认路径正确。用既有受控权限让服务账号读到必要配置；不能为了备份把秘密改成所有人可读。缺文件或权限不足应报告失败，不能略过后说完整。

远端R2须使用**不同于公开资源桶的独立私密桶**，后台原前缀不能用来证明私密：

```ini
BACKUP_R2_BUCKET=独立私密桶名称
BACKUP_R2_PRIVATE_CONFIRMED=1
```

只有维护者已经检查下列事实后，才写第二行：桶未开放公共域名/r2.dev，无公开Worker读取通道；服务凭据对备份桶具备所需最小读写权限；生命周期不提前删除400天内备份；不登录无法取得一份合成加密备份。最好使用独立账号/凭据与资源服务隔离；当前代码使用服务既有S3客户端，必须核对其实际权限。`CONFIRMED`只是人工回执标志。

生产WebDAV必须使用HTTPS，跳转不会携带凭据跟随。先在后台关闭尚未配好的远端选项，制作本地完整备份并验证；再开启已验证的远端。成功报告应含 `complete:true`、本地校验和、每个启用目标`verified:true`。任何上传、GET读回或配置失败都应 `complete:false`，本地已成功的副本仍留存。自动备份失败一小时后重试，不每分钟无休止生成新文件。

备份位置是 `DATA_DIR/private-backups/runtime-*.json.enc`；文件0600、目录0700。仅供本机保留与受控备份，不做静态公开服务。课程资源/头像对象须保留原R2存储；完整运行包只包含这些资源的索引/登记，不含对象字节。可选WebDAV课程副本另做逐对象读回验证。

### 5. 恢复演练及到期清理

以下路径均应由朋友替换成实际受控路径；恢复目标必须从未存在，不能写正在运行的目录：

```sh
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs verify /受控目录/runtime-备份.json.enc
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs restore /受控目录/runtime-备份.json.enc /新的隔离恢复目录
```

预期：验证输出`verified:true`；恢复输出`restored:true, quarantined:true, sessionsRevoked:true`。恢复后的SQLite能读到合成账号、评价/反馈归属、安全/管理员/调取日志，JSON哈希对应清单；旧会话为空，注销账号仍保持该快照中的注销状态。错口令或损坏文件必须非零退出，不能得到成功报告。

`.restore-quarantine`会阻止该目录直接启动。**旧备份拍摄之后发生的注销、删除、封禁等变化必须先核对并重新应用。D-01尚未决定，当前没有“一键解除隔离并自动上线”的工具。** 不要删除标志来绕过检查。恢复服务还需按维护流程配置秘密路径和资源桶，重建静态发布，不能把隔离目录直接当旧生产目录使用。

日常到期清理可以纳入朋友现有维护任务：

```sh
BACKUP_PASSWORD_FILE=/受控目录/口令文件 node scripts/runtime-backup.mjs prune /实际DATA_DIR/private-backups
```

仅验证后清理超过400天的备份，无数量上限淘汰。口令更换后旧包必须用旧口令单独核验/维护；无法解密时命令失败并保留，不会猜测删除。明确S5分类保留策略后再调整工程窗口。
