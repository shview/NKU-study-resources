## 你负责：导入小程序并完成真机主流程

1. 在微信开发者工具中导入上述小程序工程根目录；`miniprogramRoot` 已在项目配置中指定。若在另一台电脑已有项目，先检查并应用 `miniprogram-web-login.patch`，不要覆盖那台电脑未提交的其他修改。无需重新填写或发送小程序身份。
2. 编译后，在“我的”确认出现“网页登录确认”；通过你已有的预览／体验版流程使测试手机运行这份代码。只是手机打开旧体验版，不会获得本轮新增页面。此单未代你上传或发布。
3. 朋友确认网站可测试后，在电脑浏览器打开网站账号弹窗，选择“微信扫码”，保持该弹窗打开，复制它显示的登录码。票据约5分钟有效，操作过久应刷新。
4. 在手机打开“我的 → 网页登录确认”，粘贴登录码。在当前页完成微信登录；若提示未验证，点击“授权验证手机号”。确认看到正确的当前账号以及“手机号已验证”。
5. 点击“确认网页登录”。小程序应显示确认成功；电脑浏览器应完成登录。进入网站“我的”，确认与小程序为同一个账号且显示手机号已认证。
6. 按朋友准备的测试课程／队列提交一条带明确验收标记的内容。朋友核对后台只有一条、归属正确、状态待审、公共列表不显示。若没有受控测试条件，此步保留待验，不向普通课程投放测试评价。
7. 返回小程序“我的”，切换页面再返回，检查手机号状态仍为已验证。退出网页后再用微信流程登录一次，确认状态不会丢失。

首次优先手动输入网站登录码：网站当前默认生成 `release` 小程序码，而新增确认页尚未发布时正式版并不存在该页。手动码可以先验认证和Cookie闭环，但不等于二维码跳转已通过。

## 追加边界验收

| 操作 | 应有结果 |
|---|---|
| 获取新登录码后，在小程序取消返回 | 浏览器保持未登录；不能仅扫码即自动登录 |
| 使用已消费的旧码再次确认 | 明确过期／已用／无效，不签发第二个网页会话 |
| 等待超过5分钟后使用旧码 | 拒绝并要求回网站刷新 |
| 连续点击确认 | 本地只发一个确认请求，成功后按钮不再提交 |
| 确认时断网 | 不假报成功、不自动重发；先检查浏览器，未登录则换新码 |
| 朋友受控环境中的未认证／封禁账号 | 服务端拒绝；不得为测试修改真实用户认证状态 |

二维码验收另做一次：朋友在受控环境令服务器 `WXACODE_ENV_VERSION=trial`，并确认手机有对应体验权限及体验版本包含新页面，或在新页面正式发布后使用默认release。不要为了单次试验随意切换面向所有用户的生产扫码版本；验收记录明确使用哪种版本。扫码后应进入同一确认页、带入票据，再由本人点击确认。

当前流程登录的是小程序账号，不自动合并一个先前独立注册的网页密码账号。首次联调直接使用上述微信流程；账号绑定／合并路径仍需单独明确，不能把两个同名账号当成同一身份。
